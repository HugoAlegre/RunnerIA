Manual a prueba de tontos:
Frontend para casos de prueba

Como si fuera una clase de páginas web. Vas a aprender a armar una pantalla donde un operador elige un escenario, ve prerequisitos y lanza la prueba. No es la app final: es el manual para que vos la puedas construir.

Para quién es este manual

Para alguien que nunca programó una página (o casi) y quiere entender, sin magia, cómo se hace un frontend sencillo para listar y ejecutar casos de prueba de Automatizacion SOT.

Regla de oro del profesor Si no entendés una palabra, andá al glosario. Si un paso falla, no saltees: leé la Clase 11 (errores típicos).
Qué NO es este archivo No es el runner listo para producción. No ejecuta Playwright solo. Es un curso en HTML: abrís este archivo en el navegador y aprendés. El prototipo visual de ejemplo del proyecto se llama prototipo-simple-operador.html.

Mapa del viaje (qué vas a lograr)

Al terminar, vas a saber hacer:
  1. Un archivo .html que se abre en Chrome.
  2. Una lista de escenarios a la izquierda.
  3. Un panel a la derecha con título, tag, prerequisitos y botones.
  4. Que al hacer clic en un escenario, el panel se actualice (JavaScript).
  5. Entender cómo, más adelante, ese botón “Ejecutar” podría llamar a un script PowerShell o a una API.

Analogía: el frontend es el tablero de un ascensor. Los botones no son el motor: solo piden “piso 3”. La automatización (Playwright + SpecFlow) es el motor que mueve la cabina.

Clase 0 — Tres piezas de toda página web

Toda pantalla del navegador se arma con tres lenguajes. Memorizá esto:

Lenguaje Para qué sirve Analogía
HTML Define qué hay: títulos, botones, listas, textos. Los ladrillos y paredes de la casa
CSS Define cómo se ve: colores, tamaños, columnas. La pintura y el amoblamiento
JavaScript Define qué pasa al hacer clic: cambiar textos, mostrar datos. Los interruptores y el electricista
Ejercicio mental Si ves un botón azul “Ejecutar escenario”: el botón es HTML, el azul es CSS, y que al hacer clic cambie el texto “Corrida en curso…” es JavaScript.

Clase 2 — Carpetas, archivo y cómo abrirlo

Paso 2.1

Abrí el Explorador de Windows y andá a la carpeta del proyecto, por ejemplo:
C:\Repositorio\Proyecto\AutomatizacionSOT\AutomatizacionSOT\

Paso 2.2

Creá un archivo nuevo de texto. Renombralo a mi-runner-operador.html (importante: la extensión debe ser .html, no .txt).

Paso 2.3

Abrilo con el Bloc de notas, VS Code o Cursor. Escribí el código de las clases siguientes. Guardá. Luego hacé doble clic en el archivo: se abre en el navegador.

Trampa clásica de Windows Si no ves la extensión .txt, Windows la oculta. Activá “Extensiones de nombre de archivo” en el Explorador. Si no, podés crear mi-runner-operador.html.txt sin querer y el navegador no lo trata como página.

Clase 3 — HTML: el esqueleto mínimo

Copiá esto tal cual como base. Es la “casa vacía”. Todo lo demás se agrega adentro de <body>. 

<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Runner de pruebas SOT</title>
  <style>
    /* Acá va el CSS (Clase 4) */
  </style>
</head>
<body>
  <main class="app">
    <header>
      <h1>Runner de pruebas SOT</h1>
      <p>Elegí un caso, revisá prerequisitos y ejecutá.</p>
    </header>

    <section class="layout">
      <aside id="lista" class="panel"><!-- lista de escenarios --></aside>
      <section id="detalle" class="panel"><!-- detalle del elegido --></section>
    </section>
  </main>

  <script>
    // Acá va el JavaScript (Clase 7)
  </script>
</body>
</html>

Qué significa cada etiqueta (sin misterio)

EtiquetaTraducción humana
<!doctype html>Le dice al navegador: “esto es HTML moderno”.
<html lang="es">Documento en español.
<head>Datos internos (título de pestaña, CSS). No se ve como contenido.
<title>Texto de la pestaña del navegador.
<body>Todo lo que el usuario ve.
<main>Contenedor principal de la página.
<header>Cabecera (título y subtítulo).
<aside>Columna lateral (la lista).
<section>Bloque temático (el detalle).
id="lista"Nombre único para que JavaScript lo encuentre.
class="panel"Etiqueta de estilo para el CSS.
Práctica Guardá, abrí en Chrome. Deberías ver solo el título y el subtítulo. Si ves eso: felicitaciones, ya tenés un frontend (feo, pero frontend).

Clase 4 — CSS: que no se vea como documento Word de 1998

Dentro de <style>...</style> pegá reglas. Empezá por lo esencial: fondo, dos columnas, cajas blancas. 

:root {
  --bg: #eef2f7;
  --panel: #ffffff;
  --text: #111827;
  --muted: #6b7280;
  --line: #d8dee9;
  --accent: #0ea5e9;
}

* { box-sizing: border-box; }
body {
  margin: 0;
  background: var(--bg);
  color: var(--text);
  font-family: "Segoe UI", system-ui, sans-serif;
}

.app {
  width: min(1180px, calc(100% - 32px));
  margin: 0 auto;
  padding: 32px 0;
}

.layout {
  display: grid;
  grid-template-columns: 360px 1fr;
  gap: 16px;
}

.panel {
  background: var(--panel);
  border: 1px solid var(--line);
  border-radius: 24px;
  padding: 18px;
}

@media (max-width: 900px) {
  .layout { grid-template-columns: 1fr; }
}

Explicación corta de lo importante

  • :root { --accent: ... } → variables de color. Cambiás un valor y se actualiza en varios lados.
  • display: grid + grid-template-columns: 360px 1fr → dos columnas: izquierda fija, derecha flexible.
  • @media (max-width: 900px) → en pantallas chicas, una sola columna (apilado).
Truco del profesor No inventes 40 colores. Elegí fondo gris claro, panel blanco, texto casi negro, un solo color de acento para el botón principal.

Clase 5 — Lista de escenarios (HTML estático primero)

Primero hacelo a mano, sin JavaScript. Así entendés la estructura. Después lo automatizamos.

Clase 6 — Panel de detalle (lo que el operador lee)

La derecha tiene cuatro bloques fijos. No mezcles todo en un solo párrafo.

  1. Título + descripción + tag SpecFlow
  2. Datos de contexto (sucursal, usuario, resultado esperado)
  3. Checklist “Antes de ejecutar”
  4. Checklist “Evidencia a revisar” + botones
<section id="detalle" class="panel detail">
  <div class="detail-head">
    <div>
      <h2 id="titulo">Interpase aceptado</h2>
      <p id="descripcion">Circuito completo de pase intercaja...</p>
    </div>
    <span id="tag" class="tag">@OtrosIngresos</span>
  </div>

  <div class="info-grid">
    <div class="info"><small>Sucursal</small><strong id="sucursal">131</strong></div>
    <div class="info"><small>Usuario</small><strong id="usuario">operador</strong></div>
    <div class="info"><small>Resultado</small><strong id="resultado">Aceptado</strong></div>
  </div>

  <h3>Antes de ejecutar</h3>
  <div id="prerequisitos" class="checks"></div>

  <h3>Evidencia a revisar</h3>
  <div id="evidencias" class="checks"></div>

  <div class="actions">
    <button type="button" id="btnValidar">Validar prerequisitos</button>
    <button type="button" id="btnPasos">Ver pasos</button>
    <button type="button" id="btnEjecutar" class="primary">Ejecutar escenario</button>
  </div>
</section>
Diseño para operadores (no para programadores) Evitá jerga: no pongas “feature file” ni rutas de disco en el título. Poné nombres de negocio: “Interpase aceptado”, “Alta con apertura”.

Clase 7 — JavaScript: hacer que el clic cambie el panel

Idea: cuando hacen clic en un .scenario, leemos su data-id, buscamos los datos en un objeto, y rellenamos los id del panel.

Paso 7.1 — Función para pintar el detalle
function mostrarEscenario(esc) {
  document.getElementById("titulo").textContent = esc.titulo;
  document.getElementById("descripcion").textContent = esc.descripcion;
  document.getElementById("tag").textContent = esc.tag;
  document.getElementById("sucursal").textContent = esc.sucursal;
  document.getElementById("usuario").textContent = esc.usuario;
  document.getElementById("resultado").textContent = esc.resultado;

  document.getElementById("prerequisitos").innerHTML =
    esc.prerequisitos.map(t => `<div class="check">☐ ${t}</div>`).join("");

  document.getElementById("evidencias").innerHTML =
    esc.evidencias.map(t => `<div class="check">☐ ${t}</div>`).join("");
}
Paso 7.2 — Escuchar clics en la lista
document.querySelectorAll(".scenario").forEach(item => {
  item.addEventListener("click", () => {
    document.querySelectorAll(".scenario").forEach(x => x.classList.remove("selected"));
    item.classList.add("selected");

    const id = item.getAttribute("data-id");
    mostrarEscenario(ESCENARIOS[id]);
  });
});
Traducción línea por línea querySelectorAll = “traeme todos los que coinciden”.
addEventListener("click", ...) = “cuando hagan clic, ejecutá esto”.
classList.add("selected") = “pintalo como elegido”.
ESCENARIOS[id] = “buscá en mi diccionario el escenario 03/04/05”.

Clase 9 — Botones útiles (sin mentirle al operador)

En el prototipo estático los botones no hacen nada real. En tu versión, al menos informá qué pasaría. Eso ya es un frontend honesto. 

let escenarioActual = "03";

document.getElementById("btnEjecutar").addEventListener("click", () => {
  const esc = ESCENARIOS[escenarioActual];
  alert(
    "En una versión conectada se ejecutaría:\n" +
    esc.script + "\n\nEscenario: " + esc.titulo
  );
});

document.getElementById("btnValidar").addEventListener("click", () => {
  alert("Checklist manual:\n- " + ESCENARIOS[escenarioActual].prerequisitos.join("\n- "));
});

document.getElementById("btnPasos").addEventListener("click", () => {
  alert("Ver feature / MANUAL.md del escenario " + escenarioActual);
});

Recordá actualizar escenarioActual dentro del clic de la lista: 

escenarioActual = id;

Clase 10 — Cómo se conecta esto con AutomatizacionSOT (visión real)

Acá está la parte que muchos saltan y después se frustran. El HTML no puede, solo, ejecutar un .ps1 en tu PC por seguridad del navegador. Necesitás un “puente”.

Camino A — Solo documentación (lo que ya tenés)

  • Frontend muestra escenarios y prerequisitos.
  • El operador copia el comando o corre el script a mano.
  • Ventaja: cero riesgo, cero backend. Ideal para empezar.

Camino B — Mini servidor local (recomendado si querés “Ejecutar” de verdad)

  1. Armás un programita (Node, .NET Minimal API, Python Flask) en localhost.
  2. El botón Ejecutar hace fetch("http://localhost:5050/run/03").
  3. Ese servidor corre dotnet test o el .ps1 correspondiente.
  4. Devuelve JSON: { "ok": true, "log": "..." }.
  5. El frontend muestra OK/FAIL y link a evidencias.
// Ejemplo conceptual del botón (Camino B)
async function ejecutar() {
  const res = await fetch("http://localhost:5050/run/" + escenarioActual, {
    method: "POST"
  });
  const data = await res.json();
  alert(data.ok ? "OK" : "FALLÓ: " + data.error);
}

Camino C — Solo generar el comando

El botón copia al portapapeles algo como: 

powershell -File .\run-Intercaja.ps1

El operador pega en una terminal. Simple y seguro.

CaminoDificultadCuándo usarlo
A — Solo UI informativaFácilPrimera versión / capacitación
C — Copiar comandoFácil+Operadores con acceso a terminal
B — API localMediaCuando ya confían en el flujo
Seguridad Nunca pongas contraseñas de SOT dentro del HTML. Esas viven en appsettings.secrets.json (como ya hace el proyecto). El frontend solo muestra “usuario” enmascarado o el nombre, no el secret.

Clase 11 — Errores típicos (y cómo no volverte loco)

SíntomaCausa probableQué hacer
Doble clic y se ve código crudo Archivo guardado como .txt Renombrar a .html
Página en blanco, F12 dice error Typo en JavaScript (coma, comilla) Abrir DevTools (F12) → pestaña Console
Cannot read properties of null El id del HTML no coincide con el JS Revisar que exista id="titulo" etc.
Clic no hace nada Script arriba del HTML, o no hay data-id Poner el <script> al final del body
Estilos no aplican Class mal escrita (scenaro) Copiar nombres exactos
fetch falla por CORS API local sin permitir el origen del HTML Servir el HTML desde el mismo servidor, o configurar CORS
Método anti-pánico 1) ¿Se ve el HTML? 2) ¿Se ve el CSS? 3) ¿La Console muestra error? No cambies tres cosas a la vez. Cambiá una, guardá, recargá (F5).

Examen final — Checklist a prueba de tontos

Marcá mentalmente. Si falta uno, volvé a esa clase.

  • Sé qué es HTML, CSS y JavaScript (Clase 0).
  • Tengo un archivo .html que abre en el navegador (Clase 2–3).
  • Hay dos columnas: lista + detalle (Clase 4–6).
  • Cada escenario tiene data-id y datos en un objeto ESCENARIOS (Clase 5 y 8).
  • Al hacer clic cambia el panel (Clase 7).
  • Los botones no mienten: informan script o llaman API (Clase 9–10).
  • No hay secretos en el HTML (Clase 10).
  • Sé abrir F12 y leer un error de Console (Clase 11).

Anexo A — Orden recomendado de construcción

  1. Esqueleto HTML vacío con título.
  2. CSS de dos columnas.
  3. 3 escenarios hardcodeados en la lista.
  4. Panel de detalle hardcodeado (sin JS).
  5. Objeto ESCENARIOS.
  6. Clic que cambia el detalle.
  7. Botones con alert honestos.
  8. (Opcional) Copiar comando PowerShell.
  9. (Opcional) API local que ejecuta el script.
